`screenNavigation(screen)` gives the navigation of a screen to code outside React that knows which screen it acts
for: a class a screen creates, a listener that gets the screen with an event, a `screenProvider`. It returns the same
object as [`useNavigation()`](/api/moving-between-screens/useNavigation) in that screen, so its commands act from that
screen and take no ids.

## Usage {#usage}

A chat screen creates a session object that lives outside React. When the other side ends the call, the session closes
the screen it belongs to:

```ts title="src/chat/ChatSession.ts"
import { screenNavigation } from '@apexnative/navigation';
import type { ScreenInfo } from '@apexnative/navigation';

export class ChatSession {
  constructor(private readonly screen: ScreenInfo) {}

  // called by your own socket when the call ends
  onEnded() {
    screenNavigation(this.screen).goBack();
  }
}
```

```tsx title="src/screens/Chat.tsx"
import { useState } from 'react';
import { useScreen } from '@apexnative/navigation';
import { ChatSession } from '../chat/ChatSession';

function Chat() {
  const screen = useScreen();
  const [session] = useState(() => new ChatSession(screen));
  // …
}
```

When the call ends, Chat goes back, or its modal closes, even if the user has opened another tab meanwhile. With
`navigation.goBack()` instead, the session would close whatever the user is looking at.

A listener gets the screen with every screen event, so it can act on that screen. Here ⌘F on an iPad keyboard opens
Search over whichever screen has the shortcut in its `keyCommands`:

```ts
navigation.on('keyCommandPressed', ({ screen, keyCommandId }) => {
  if (keyCommandId === 'search') {
    screenNavigation(screen).push('Search');
  }
});
```

## Signature {#signature}

<ApiSignature data={data} name="screenNavigation" />

It takes the screen as `{ id, name }` and returns a `ScreenNavigation`. A new object on every call: in a component,
`useNavigation()` keeps one for the screen.

## The screen it takes {#screen-info}

The `screen` is a `ScreenInfo`, as `useScreen()` returns it, and as every screen event, `screenProvider` and
`errorFallback` give it.

### `id` {#id}

<ApiMember data={data} of="ScreenInfo" name="id" />

The id of this showing of the screen, made by the navigation: `Component12`. The commands go by it. A screen that has
closed keeps its id, and its commands reject: "the screen 'Component12' is gone". Don't keep a `ScreenInfo` past the
screen's life; drop it on `screenPopped` or when the screen unmounts.

### `name` {#name}

<ApiMember data={data} of="ScreenInfo" name="name" />

The name of the screen in `screens`: `'Chat'`. The commands don't use it; it is there for your own checks and logs.

## Where the screen comes from {#sources}

| Where | How |
| --- | --- |
| A component of the screen | `useScreen()`, or `useNavigation()` directly. |
| A screen event | `navigation.on(…)` and `listeners` give `event.screen`. |
| A button's press | `onPress` gets `navigation` of its screen already. |
| `screenProvider`, `errorFallback` | Their `screen` prop. |
| A command | `push` and `showModal` resolve with an id; the name is the one you passed. |

A screen of an overlay or of a side menu's menu acts from elsewhere, as in a component: the overlay from the screen the
user sees, the menu from its center. See [The stack](/api/moving-between-screens/useNavigation#stack-group).
